# Email drafts

Original black and white, single-column email layouts. Open [the preview index](index.html), then choose a draft. No messages are sent. These are proposed templates; the existing runtime email renderer is unchanged.

## Design

White #FFFFFF message body, near-black #111111 wordmark and CTA, off-white #F5F5F5 header text, muted #555555 secondary text and #E5E5E5 dividers. Arial/Helvetica are safe email fonts; web-font downloads are not required. The table-based layout is capped at 600px, with a single full-width content flow and a text-link fallback. No external images, tracking pixels or invented brand logo are included.

## Placeholders and safe integration

- `{{brand_name}}`: final store name; currently undecided.
- `{{confirmation_url}}`, `{{reset_url}}`, `{{password_recovery_url}}`: validated account action URLs generated by the authentication provider. These are generic draft placeholders, not Supabase dashboard template syntax; map to the provider-supported fields before activation.
- `{{order_url}}`, `{{request_url}}`: absolute private account URLs; sign-in must remain required.
- `{{order_reference}}`, `{{item_summary}}`, `{{delivery_charge}}`, `{{order_total}}`: authoritative order snapshot values, with PKR formatting. These amounts do not include invented taxes/discounts.
- `{{contact_url}}`: the staffed, published contact page.
- `{{launch_confirmation_url}}`, `{{unsubscribe_url}}`: distinct token-based actions; opening a link alone must not change consent.
- `{{collection_url}}`: published collection URL after launch.

HTML-escape substituted text and attribute values. Validate action URLs against allowed HTTPS destinations before inserting them. Never include passwords, access tokens unrelated to the email action, full delivery addresses or phone numbers. Populate drafts server-side; do not fetch private order data from the public browser preview. Replace every placeholder before sending.

## Activation boundaries

The current worker handles order-status, support-reply and launch-confirmation jobs using its existing basic renderer. These HTML drafts have not replaced it. Signup/recovery delivery uses Supabase Auth separately. Password-change notices and launch broadcasts need their own verified event and consent logic; they are draft-only features. A verified sender, authentication redirect settings, SPF/DKIM/DMARC configuration and real inbox acceptance are separate launch work. No credentials or sender subscription were configured by generating these drafts.

Use a text alternative alongside HTML. Suppress all order emails for simulated orders. Launch announcements require confirmed and still-active consent, working unsubscribe handling and final products. Security and transactional messages should not contain promotional copy. Test Gmail, Outlook and mobile mail clients before enabling any sending.
